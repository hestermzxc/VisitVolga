# Сверка афиши Visitvolga: инструкция

Программа `afisha_sync` сверяет афишу сайта с сайтами-источниками и готовит файлы для загрузки в Битрикс. Работа занимает несколько минут. Вам остаётся проверить отмеченные строки и загрузить файлы.

Сама программа на сайте ничего не меняет. Изменения попадают на сайт только через ваш импорт.

---

## 1. Что делает программа

Программа сравнивает выгрузку афиши из Битрикса с источниками:

- **afisha21.ru** — анонсы и театральная афиша по месяцам;
- **официальные сайты площадок**, например афиша Русского драмтеатра. Их данные имеют приоритет для совпавших показов.

Каждое будущее событие сайта попадает в одну из групп:

| Результат | Что это значит |
|---|---|
| Совпадает | всё как в источнике, ничего делать не нужно |
| Изменилось | в источнике другая цена, время или площадка; правка попадёт в файл обновления |
| Новое | событие есть в источниках, но не на сайте; попадёт в файл новых событий |
| Нет в источниках | событие есть только на сайте; его нужно проверить вручную |

## 2. Подготовка (один раз)

1. **Установите Python 3** с [python.org](https://www.python.org/downloads/). При установке отметьте галочку **Add Python to PATH**.
2. **Скопируйте папку `afisha_sync`** к себе на компьютер. В ней должны быть файлы:
   - `run.bat` — запуск;
   - `config.xml` — настройки;
   - `afisha_sync.py`, `parsers.py`, `compare.py`, `report.py` — сама программа (их не трогать);
   - `fix_xml_id.php` — разовый скрипт для админки.
3. **Один раз запустите `fix_xml_id.php`** в админке Битрикса. Это нужно, потому что сейчас у части событий-копий на сайте одинаковые внешние коды, и импорт может обновить не тот элемент. Порядок такой:
   1. Откройте **Настройки → Инструменты → Командная PHP-строка**.
   2. Вставьте содержимое файла **без первой строки `<?php`**.
   3. Запустите как есть (`$dryRun = true`). Скрипт только покажет список элементов, у которых изменится внешний код.
   4. Проверьте список, замените в коде `$dryRun = true` на `$dryRun = false` и запустите ещё раз.

   После этого шага файл `import_updates_after_fix.csv` больше не понадобится: все обновления будут попадать в `import_updates_now.csv`.

## 3. Регулярная сверка

Сверку удобно делать раз в неделю.

### Шаг 1. Выгрузите афишу из Битрикса

1. Откройте в админке **Контент → Инфоблоки → Экспорт CSV**.
2. Выберите инфоблок афиши и поля, как в прошлой выгрузке: `IE_XML_ID`, `IE_NAME`, `IE_ID`, `IE_ACTIVE`, `IE_ACTIVE_FROM`, `IE_ACTIVE_TO`, `IE_CODE` и свойства `IP_PROP17`, `IP_PROP18`, `IP_PROP19`, `IP_PROP20`, `IP_PROP27`, `IP_PROP28`, `IP_PROP43`, `IP_PROP44`, `IP_PROP46`, `IP_PROP47`, `IP_PROP53`.
3. Укажите разделитель **«;»** и кодировку **UTF-8**.
4. Сохраните файл в папку на уровень выше `afisha_sync`, например `C:\vse\Visitvolga\`.

Выгрузка каждый раз должна быть **свежей**. Иначе программа предложит повторно добавить события, которые вы уже загрузили.

### Шаг 2. Укажите файл в настройках

Откройте `config.xml` в Блокноте и впишите имя нового файла в строку:

```xml
<export>../export_file_ИМЯ_ФАЙЛА.csv</export>
```

`../` означает «папка на уровень выше». Если имя файла не меняется, этот шаг можно пропустить.

### Шаг 3. Запустите программу

Дважды щёлкните **`run.bat`**. Откроется чёрное окно. Программа:

1. при первом запуске сама установит библиотеки для Excel и разбора страниц;
2. скачает афишу с каждого сайта и напишет, сколько событий нашла;
3. сверит её с выгрузкой и напишет итог.

Выглядит итог примерно так:

```
Готово: C:\vse\Visitvolga\sverka_2026-11-07
  совпадают без изменений: 55
  обновить сейчас:         24  (import_updates_now.csv)
  обновить после fix:      0   (import_updates_after_fix.csv)
  новые события:           31  (import_new_events.csv)
  нет в источниках:        4
```

Результаты лежат в папке `sverka_ГГГГ-ММ-ДД` рядом с выгрузкой. Нажмите любую клавишу, чтобы закрыть окно.

## 4. Как читать отчёт

Откройте `afisha_sverka.xlsx`. **Жёлтые строки нужно проверить**, остальные можно не смотреть.

| Лист | Что там | Что делать |
|---|---|---|
| **Сводка** | итоговые цифры, порядок загрузки, какие источники прочитались | проверить, что все источники загрузились без ошибок |
| **Изменения** | что поменяется у существующих событий: было → стало, источник, решение | прочитать жёлтые строки (см. ниже) |
| **Новые** | события к добавлению: название, дата, площадка, цена | прочитать жёлтые строки, колонка «Проверить» |
| **Нет в источниках** | события сайта, которых не нашлось в источниках | проверить вручную: перенесено, отменено или источник его не публикует |
| **Пропущено** | анонсы, которые программа не смогла разобрать (нет конкретной даты) | при желании добавить вручную |

### Что значат пометки

**Лист «Изменения», колонка «Решение»:**

- **будет обновлено** — правка попадёт в файл импорта;
- **источники расходятся — не применяется** — два источника дают разные данные. Проверьте на сайте площадки и, если нужно, добавьте ручное решение (раздел 6);
- **площадка отличается** — на сайте событие привязано к другому месту. Чаще всего это ошибка на сайте. Проверьте и добавьте ручное решение;
- **не применяется / проверено вручную** — сработало ручное решение из `config.xml`.

**Лист «Новые», колонка «Проверить»:**

- **название собрано из имени артиста** — в анонсе было только имя («ДК Ухсая Сергей Трофимов»), и программа сделала название «Выступление Сергея Трофимова». Проверьте склонение;
- **проверить название: нет типа события** — название начинается с кавычек («Soprano Турецкого»). Можно дописать «Концерт», «Шоу» и т. п.;
- **площадка не распознана** — программа не знает эту площадку. Добавьте её в `config.xml` (раздел 6) и запустите сверку ещё раз;
- **цена в источнике была перевёрнута — исправлено** — в источнике была опечатка вроде «4000–1200», программа поменяла числа местами;
- **цена / время не указаны в источнике** — так и есть, поле останется пустым.

Поправить название или цену можно двумя способами: прямо в CSV перед загрузкой (открыть в Excel и сохранить как CSV UTF-8 с разделителем «;») или в админке после загрузки.

## 5. Загрузка в Битрикс

Загружайте файлы **в этом порядке**:

| № | Файл | Когда |
|---|---|---|
| 1 | `import_updates_now.csv` | всегда |
| 2 | `fix_xml_id.php` | только если он есть в папке результатов (раздел 2, шаг 3) |
| 3 | `import_updates_after_fix.csv` | только после шага 2 |
| 4 | `import_new_events.csv` | всегда |

Импорт делается в **Контент → Инфоблоки → Импорт CSV**:

- инфоблок — афиша;
- разделитель — **«;»**, кодировка — **UTF-8**, первая строка — названия полей;
- **«Что делать с элементами, отсутствующими в файле» — обязательно «ничего не делать».**

> ⚠️ Если выбрать «деактивировать» или «удалить», Битрикс снимет с публикации или удалит **всю остальную афишу**: в файле только изменённые и новые события.

При первом использовании сначала загрузите пробный файл из 2–3 строк. Проверьте в админке, что у элементов правильно заполнились поля и вкладка «Разделы» и что события отображаются на сайте.

Новые события загружаются **сразу активными** и появляются на сайте после импорта.

## 6. Настройка `config.xml`

Открывайте файл в Блокноте или любом редакторе. После правки сохраните его в кодировке **UTF-8**: в Блокноте это «Сохранить как → Кодировка: UTF-8».

### Добавить сайт с афишей

Найдите блок `<sources>` и добавьте строку:

```xml
<source url="https://ссылка-на-страницу-афиши/" name="Как подписать в отчёте"/>
```

Если это официальный сайт одной площадки, добавьте её код из списка «Где» и пометку «главный»:

```xml
<source url="https://rusdram21.ru/afisha/" name="Русский драмтеатр" venue="N9yWUgtr" official="true"/>
```

| Параметр | Зачем |
|---|---|
| `url` | ссылка на страницу с афишей (обязательно) |
| `name` | подпись в отчёте |
| `venue` | код площадки на сайте, если все события источника проходят в одном месте |
| `place` | текст площадки с адресом, если кода нет: `place="Клуб «Неон» (ул. Мичмана Павлова, 12)"` |
| `official="true"` | официальный сайт: его данные имеют приоритет для совпавших показов |
| `months` | для afisha21: на сколько месяцев вперёд смотреть (по умолчанию 4) |
| `enabled="false"` | временно отключить источник |

Программа умеет читать:

- **afisha21.ru**;
- **официальные афиши Русского и Чувашского драмтеатров, Камерного театра, Театра кукол, МАЙтеатра и Станиславский.com**;
- **страницы с разметкой мероприятий schema.org**. Такая разметка есть на многих билетных сервисах и сайтах театров, например на ticketform.ru.

Если после запуска по новому сайту написано **«событий не найдено»**, программа не умеет его читать. Обычно так бывает, когда афиша показывается виджетом продажи билетов. Для такого сайта нужен отдельный модуль, обратитесь к разработчику.

### Где взять код площадки

Код — это значение поля «Где» (`IP_PROP17`) в выгрузке. Откройте выгрузку в Excel, найдите любое событие этой площадки и скопируйте значение из колонки `IP_PROP17`. Например, `Ewd68p4y` — это ДК Ухсая.

### Добавить площадку

Если в отчёте написано **«площадка не распознана»**, добавьте её в блок `<venues>`.

Площадка из списка «Где» (с кодом):

```xml
<venue name="ДК Ухсая" code="Ewd68p4y">
  <pattern>ДК Ухсая</pattern>
</venue>
```

Площадка без кода, с текстом и адресом:

```xml
<venue name="Бар «Пир»" place="Бар «Пир» (пр-т Ленина, 7)">
  <pattern>баре «Пир»</pattern>
</venue>
```

- `pattern` — как площадка написана в анонсе afisha21 **после «в»/«на»**, в том же падеже: «в **баре «Пир»**», «в **Филармонии**». Строк `pattern` может быть несколько.
- `theatre` — как театр назван в театральной афише afisha21, если это театр: `<theatre>Камерный театр</theatre>`.

Адрес можно посмотреть на странице площадки на cheb.ru: на неё ведут ссылки из анонсов afisha21.

### Исправить ошибку источника (ручные решения)

Источники иногда ошибаются. Например, на afisha21 бывает неверное время, которое отличается от официального сайта. Решения записываются в блок `<decisions>` и применяются при каждом запуске.

**Не применять правку** (`reject`): нужны ID элемента и поле («Время» или «Цена»).

```xml
<reject id="2281" field="Время">театр кукол: 21.11 начало 10:30 — на сайте верно</reject>
```

**Задать значение вручную** (`force`): нужны ID элемента и поля в том виде, как в выгрузке.

```xml
<force id="5470" reason="maiteatr.ru: от 800 рублей">
  <field name="IP_PROP19">800–2500 руб.</field>
</force>
```

Часто используемые поля:

| Поле | Что это |
|---|---|
| `IE_NAME` | название |
| `IE_ACTIVE_FROM` | начало активности = дата и время события, формат `20.11.2026 20:00:00` |
| `IP_PROP28` | дата и время текстом: `20 ноября 20.00` |
| `IP_PROP19` | цена |
| `IP_PROP17` | площадка (код) |
| `IP_PROP43` | площадка текстом с адресом |

Решения по прошедшим событиям можно удалять.

## 7. Частые вопросы

**Окно `run.bat` сразу закрылось или пишет «python не найден».**
Python не установлен или не добавлен в PATH. Переустановите его с галочкой **Add Python to PATH** (раздел 2).

**Ошибка про `config.xml`.**
В файле сломалась разметка: не закрыт тег или стоят лишние кавычки. Сравните исправленное место с примерами из раздела 6. Кавычки-ёлочки «» внутри текста допустимы, а прямые кавычки `"` внутри значения параметра — нет.

**В отчёте у источника «ошибка» или «не загрузилось».**
Сайт был недоступен. Запустите сверку позже. Остальные источники при этом всё равно обрабатываются.

**Файл отчёта не перезаписался.**
Старый отчёт был открыт в Excel. Программа сохранила новый под другим именем, `afisha_sverka_<число>.xlsx`, в той же папке.

**Декабрьские спектакли попали в «Нет в источниках».**
Источник ещё не опубликовал этот месяц. В комментарии так и написано: «источник публикует афишу этой площадки только до …». Повторите сверку позже.

**Программа предлагает добавить события, которые уже есть на сайте.**
Вы использовали старую выгрузку. Сделайте свежую (раздел 3, шаг 1).

**Одно и то же событие предложено дважды.**
Скорее всего, площадка в анонсе не распознана, и программа не поняла, что это то же событие, что в театральной афише. Добавьте площадку в `config.xml` и запустите сверку снова.
